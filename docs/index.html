quantsim

Lookahead

Orders fill at the next bar's open, so signals cannot see their own fill#

Lookahead means a backtest uses a price it could not have known when it decided to trade. In quantsim a strategy sees bar T's close, so its order waits for bar T+1 and fills at that bar's open.[E4] A flag, SAME_BAR_OPEN_LOOKAHEAD, reproduces the old bug so its effect can be measured.

The gap has no fixed sign: same-bar fills move the momentum strategy by −0.2 pp on the same series. A test over 50 seeded random walks checks that the next-open default gives a close-peeking strategy no edge.

Overfitting

After 28 trials, the deflated Sharpe certifies no edge#

Trying many settings and keeping the best inflates the Sharpe ratio. The deflated Sharpe ratio is the probability that the chosen setting beats the best of the same number of unskilled ones. Here the walk-forward tried 4 settings in each of 7 windows, 28 trials in all, and the deflated Sharpe is 0.00, below the usual 0.95 bar.[E8]

Stitched together, the out-of-sample windows returned −4.0% after 0.1% commission + 0.1% slippage per trade; buy-and-hold, with no costs, returned −19.3%. The check is designed to withhold certification when the best of many settings could be luck, and here it does.

Costs

Every published backtest runs with its engine's default costs#

The vectorized engine charges 0.1% commission + 0.1% slippage on every trade by default.[E6] Walk-forward results above use those defaults; the fill-timing runs use the event engine's own defaults, volume-proportional slippage (k = 0.1) and no commission.[E11]

Design

Two engines trade the same signal one bar later and reach the same result#

The parity test feeds both engines one seeded series of 400 bars whose opens equal their closes, so a fill at bar T+1's open and at bar T+1's price are the same trade. It requires equal round-trip counts and total returns within 0.5 pp, with costs off in both.[E3] The event engine is the reference for order handling; the vectorized engine is for sweeping parameters.

Speed

Event-driven time grows with the number of assets; vectorized time stays flat#

Vectorized time is flat from the smallest to the largest run, consistent with fixed costs (signal setup and analytics) dominating rather than the per-asset loop; this benchmark does not separate them. Even the slowest vectorized run beat the fastest event run by 410× at 50 assets.

Speed is what makes the robustness checks routine: the walk-forward above runs 28 vectorized backtests plus one per window for scoring, and the cost sweep one per level.

Limitations

Results cover synthetic prices, one strategy and one machine#

  • Synthetic data only. Every number here comes from seeded random prices with regime shifts (benchmark seed 7, report seed 20240611); no market data is committed, so nothing here measures a real edge.
  • One machine, one strategy. Timings are from one Apple M5 Pro and the SMA crossover only; the speed ratio depends on both.
  • Shared machine. Load average 4.95 / 6.47 / 6.75 at the start of the benchmark; whiskers show spread within the session only.
  • Unadjusted bars. Real prices are stored unadjusted with split and dividend factors applied when read; the event engine's bar events carry the raw open but the adjusted close, so on real data a split day can show a false gap. Synthetic data has no adjustments.[E12]
  • Survivorship bias. The default download list is today's large caps, so long real-data backtests favour survivors.
  • In-sample cost sweep. The cost-sensitivity parameters were chosen on the same data they are scored on.
  • Daily bars, equities. No intraday data and no options backtesting; paper trading by default, live trading needs two explicit opt-ins.

Reproduce

Reproduce it in five steps#

Commands run from a clone of allenwang0/quantsim.

  1. Install with every extra (Python 3.11+, uv).

    make setup

  2. Write the seeded synthetic prices and rebuild the demo results with the default costs.

    uv run python tests/fixtures/make_fixture.py
uv run quantsim report --prices tests/fixtures/synthetic_prices.csv \
    --strategy sma momentum --out results/demo --card

  3. Time both engines (5 runs × 3 sizes; about 6 minutes here).

    make bench

  4. Run the offline tests and record the count; expect “226 passed, 6 deselected”.

    uv run python scripts/record_tests.py

  5. Rebuild this page and the README block from the committed results, then check them.

    python3 scripts/build_report.py --readme README.md
uv run pytest tests/test_build_report.py -q
